An AI that learns to play on its own.

Nobody programmed it when to jump. It looks at the screen the way a person would, boils it down to four numbers about the nearest obstacle, and discovers through reinforcement learning (trial and error with rewards and penalties) the exact moment to jump in Chrome's dinosaur game.

In plain words

What it is and why it matters

What is reinforcement learning?

A way to train AI without giving it the right answers. An agent acts, gets a reward or a penalty and, after thousands of attempts, learns what to do in each situation to collect the biggest reward. It's how a person learns to ride a bike: by falling.

The problem

The game only offers pixels, and jumping on time depends on distance, obstacle size and a speed that keeps increasing. A fixed rule ("jump at this many pixels") works at one speed and fails at another.

The solution

Computer vision turns the screen into data, and a neural network learns from 800,000 game steps when to jump. A fixed-rule script is included too, to compare the AI against traditional programming.

Step by step

How it plays and learns

A loop that keeps running while the game is on, with no access to the game's code or memory.

Capture

Grabs a 600 × 190 pixel region of the screen in real time, right where the dinosaur runs.

See

OpenCV (a computer-vision library) turns the image black and white and locates the nearest obstacle: where it starts, where it ends and how tall it is.

Decide

The neural network receives the last 4 observations to infer speed and picks: do nothing or jump. To jump, the program presses the space bar.

Learn

It earns +1 for every moment it survives and −500 when it crashes. When it spots the game-over screen, it restarts the run and tries again.

Capabilities

It learns to play like a person: by watching

No tricks, no access to the game's code. Just the screen, eyes (computer vision) and experience.

Plays without reading the game's internals

Everything it knows comes from the image. It scans the strip in front of the dinosaur column by column and sums it up in four numbers: the distance to the start and end of the obstacle, and its highest and lowest point. When the path is clear, it gets "safe" values.

Infers speed

A single image can't tell how fast the cactus is coming. So it stacks the last 4 observations: 16 numbers in total.

Knows when it lost

It recognizes the GAME OVER screen by comparing it against a reference image (template matching) at an 80% match.

Two approaches to compare

The trained network vs. a rule-based script that jumps when a dark pixel crosses a line in front of the dinosaur and adapts if the background color changes.

Training that isn't lost

It saves a checkpoint every 10,000 steps, saves when you press the q key, and makes an emergency save if anything fails.

Shows what it "sees"

A debug mode opens a window with the black-and-white image the AI is analyzing and the obstacles it detects. It's used to calibrate the capture region on each monitor and gives full transparency into what it perceives.

Under the hood

How it's built

DQN (Deep Q-Network)

A neural network estimates the "Q value" of each action, how much future reward it expects if it jumps or does nothing, and picks the highest. Built with Stable-Baselines3 and an MLP policy (a network of fully connected layers).

Custom Gymnasium environment

Gymnasium is the standard for defining reinforcement-learning environments. Here: 2 actions, an observation of 4 integers, and a reward of +1 per step and −500 on a crash.

Experience memory

A 100,000-step replay buffer stores past plays so it can learn from them again. Learning rate: 0.0005.

Controlled exploration

At first it acts almost at random to discover the game; during the first 10% of training, exploration drops from 100% to 1%.

800,000 steps, CPU only

Trained with PyTorch on the processor (Intel Core i7-13700HX), with no graphics card. The documentation estimates about 17 hours for a full training run.

Capture and control

mss captures the screen, OpenCV processes it, pyautogui presses the jump key and pynput listens to the keyboard to stop and save.

A university capstone project for an Automation and Robotics course, built as a team and documented with an installation and usage manual. Known limitation: coordinates are calibrated for a 1920 × 1200 screen and Chrome in dark mode; on another screen the capture region must be adjusted.

All the code is open: the environment, the training and the script that loads the model and plays autonomously.
