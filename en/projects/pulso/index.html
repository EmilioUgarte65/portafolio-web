Customer satisfaction surveys

Surveys that work anywhere, signal or not.

Pulso is a PWA (an app you install from the browser) for measuring customer satisfaction at each branch. A tablet in kiosk mode asks questions with smiley faces, options or text; answers are saved on the device and sync on their own when the connection returns. At the office, a dashboard shows results in real time and exports them to Excel and PowerPoint.

In plain words

What it is and why it matters

What is it?

A survey system with two sides: the kiosk screen, which customers answer on their way out, and the admin panel, where questions are set up and results are read.

The problem

Nobody types up paper surveys and almost nobody answers survey links. If the survey depends on the internet, every network drop is a lost opinion, and results arrive late.

The solution

A question in plain sight, answered with one tap and never lost even without a network. If the rating is bad, it asks what to improve; if satisfaction drops below target, it alerts the office.

Step by step

How a survey works

The customer rates

Tap a face, pick an option or write a comment. Open questions can be skipped.

Follow-up

If the rating is bad, a follow-up question appears, such as “What can we improve?”.

Saved and sent

When finished, the whole survey is saved on the device and sent as a single batch. If the customer walks away halfway, it resets and is discarded.

The office sees it

The dashboard updates live. If the index drops below target an alert arrives, and reports export to Excel or PowerPoint.

Features

Measure satisfaction, no excuses

Built for branches with poor signal and for anyone to use without training.

Offline capture

Every answer is saved on the tablet instantly. Staff never wait for a signal to keep surveying.

Three question types

Smiley faces with editable labels, multiple choice and open text.

Follow-up questions

They show up or not depending on the rating the customer gave.

Kiosk mode

Resets itself after a while without use, with extra time on text questions. The timer does not run on the first question, so it never resets when nobody has started.

Schedules and caps

Time slots with a survey cap; once full it shows a thank-you message, different from the “outside hours” message.

Surveys per branch

Questions grouped into surveys and ordered by drag and drop.

Real-time dashboard

Metrics, trends and satisfaction index by branch and by question, with filterable open comments.

Excel and PowerPoint

Filtered data in .xlsx and a presentation with charts in .pptx.

Alerts

Push notifications (alerts that arrive even when the app is closed) when satisfaction falls below target.

How it is built

A PWA with its own server

One project with the kiosk app, the dashboard and the API.

React 18, TypeScript and Tailwind

React interface with TypeScript (JavaScript with types) and Tailwind CSS styling, bundled with Vite.

Express 5 API

A REST API (the door the app uses to request data from the server, organized around resources) with routes for votes, questions, branches, surveys, metrics, users and audit, written in TypeScript.

Prisma and SQL Server

Prisma is an ORM: a layer that translates code into database queries. The data lives in SQL Server.

Real time with Socket.io

Socket.io keeps an open connection with the dashboard so new votes appear without reloading the page.

Older iPads

A compatibility plugin builds a version for Safari 12, so tablets that no longer get updates stay useful.

Isolated QA

A QA (testing) environment with its own database in Docker, fully separated from production.

Offline and security

Reliable on the worst internet

Offline-first with IndexedDB

Offline-first means the app works on the device first. With Dexie, a layer on top of IndexedDB (the browser’s built-in database), every vote is saved as “pending” before it tries to send.

Retries and cleanup

With no network it retries on the next cycle; after several failures the vote is flagged for review. Synced votes are removed from the device after a week.

Batch sending

The whole survey travels in a single request, so no loose answers are left from a half-finished survey.

JWT with refresh

Access uses JWT (a signed token that proves who you are): a short-lived access token and another one to renew it. Passwords are stored hashed with bcrypt.

Two roles

Administrator, with the full panel, and branch, with the kiosk screen and its own dashboard.

Audit log

Every action in the system is recorded: who did what and when.
