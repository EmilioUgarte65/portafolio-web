Ruta Clara · Logistics and maps

Delivery routes on real streets, built for trucks.

Ruta Clara plans home deliveries for a company with several vehicles and warehouses. It computes street-by-street routes with a right-turn rule, respects which vehicle can enter each zone, builds the warehouse loading plan and compares the result with the current way of delivering. It uses open maps (OpenStreetMap) and custom algorithms, with no paid APIs (services for programs).

In plain words

What is it and what is it for?

What is vehicle routing?

Deciding which vehicle carries each order, in what sequence and along which streets, while respecting capacity, time windows and access permits. In technical literature it is called the VRP (Vehicle Routing Problem).

The problem

A regular GPS finds the fastest route for a car, not for a loaded truck: it does not know that a left turn across traffic is slow and risky, or that a trailer cannot enter certain streets. And stop order is decided by eye.

The solution

Ruta Clara turns the city into a graph (a network of street segments and intersections) where each turn costs differently per vehicle, and an optimizer splits orders across the fleet. Every plan is compared with "how it is done today" using the same metrics.

Step by step

A delivery day

Dispatch plans

Loads the day's orders, exported from the ERP (the sales system), and hits plan.

The optimizer decides

Assigns orders to vehicles and trips, and compares three scenarios: how it is done today, optimized without the rule, and Ruta Clara.

Warehouse loads

Gets each trip's loading plan: last delivery goes in first, with a checklist.

The driver delivers

Navigates with in-app GPS and closes each delivery with a photo and the recipient's name. The customer tracks the order through a link.

Capabilities

From the street to the loading plan

Custom algorithms on open maps, with no paid APIs.

Streets, directions and turns

Routes respect one-way streets, speed, weight and height limits, and banned turns. The right-turn rule is adjustable: every left or U-turn has its own cost per vehicle type.

Three strategies

Compares the Ruta Clara route against "fastest" (like a regular GPS, ignoring turns) and "shortest".

Vehicle restrictions

Which vehicle can enter each place: permit zones and streets closed to heavy loads.

Fleet optimizer

Multiple warehouses, multiple trips per vehicle, capacity, time windows and permits, in one plan.

Loading plan

Loading order and position of each order inside the vehicle.

Suggested transfers

Store-to-store transfers fit where a trip already heading there has spare room; if not worth it today, they wait for another day.

No empty returns

After a trip, the vehicle heads straight to the warehouse of its next load, with staggered departures by loading dock.

Driver GPS

Turn-by-turn navigation in the app: Spanish voice, vibration on every turn, speedometer with the street limit, automatic rerouting that respects the vehicle's direction, and an offline queue to close deliveries without signal.

Customer tracking

Each order has a link with an unguessable code. With no account or app, the customer sees the status, a live ETA and, at the end, the proof-of-delivery photo. The link expires and can be revoked.

Rule profiles

Balanced, maximum savings, punctuality first or safety, and each rule can be tuned. Before saving, the day is simulated: if results get worse, the comparison is shown and confirmation is required.

A role for everyone

Admin (fleet, warehouses, zones and costs), dispatch (orders, plans and live map), warehouse (loading plan), driver (their stops) and customer, with no account.

Under the hood

How it is built

Road graph from OpenStreetMap

Streets are downloaded from the open OpenStreetMap and turned into segments with direction, speed, weight and height limits, and banned turns.

Edge-based Dijkstra

Dijkstra is the classic shortest-path algorithm. Here it walks segments instead of intersections, so each turn (right, left or U-turn) has its own cost in time and diesel.

Fleet metaheuristics

The initial plan is built with Regret-2 and improved with ALNS (adaptive search that destroys and repairs parts of the solution), simulated annealing and 2-opt.

Parallel computation

Travel-time matrices between all of the day's points are computed with workers (parallel threads). In the demo, the original engine runs in a browser Web Worker over a public road network.

Node.js, React and MapLibre

Node.js API and React app with MapLibre (vector maps). No database and no paid APIs; deployed with Docker and HTTPS.

Safety guardrails

Role-based sign-in checked on every request, driver consent before sharing location, and official speed limits only, never estimates. The algorithm has automated tests.
