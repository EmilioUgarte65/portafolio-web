Custom construction management

Budgets, progress and payments for every site, in an app that keeps going offline.

Vértice is a full-stack application (with its own interface and server) custom-built to manage construction projects with outside contractors. Each project has its budget and its quotes broken into line items; the contractor reports progress with photos and requests payment, and the administrator approves or rejects it. It is offline-first: it works on the device first and syncs when the signal returns.

In plain words

What it is and why it matters

What is it?

A management app built for one specific process: tracking how much progress has been made and how much has been paid on each line item (each unit of work) of a construction project.

The problem

Progress reports arrive by chat, photos get lost in the thread and payments are tracked in spreadsheets. That makes it easy to pay twice for the same progress or to overpay, and construction sites often have no signal.

The solution

Every payment starts from progress backed by evidence and stays tied to its line item. The system calculates what has been paid, what is available and the project’s progress, and blocks requests that break the rules.

Step by step

How a payment flows

Set up the project

The administrator creates the project with its budget and assigns contractors.

Quote by line item

The contractor enters a quote split into line items, with subtotal, VAT (value-added tax) and total.

Report progress

From the site, the contractor enters the new percentage for a line item and attaches photos or PDFs, even with no signal.

Approve or reject

When the administrator approves, progress and balance update on their own; when rejecting, they leave a comment so the contractor can fix and resubmit.

Features

Your process, in one app

Replaces spreadsheets, chats and paper forms with a tool built around the real process.

Projects with budget and progress

Per project: how much has been spent, how much is left, what share of the budget is used and the average operational progress of its quotes.

Quotes by line item

Each line item has an authorized amount; paid and available amounts are recalculated with every approval.

Evidence

Photos (JPG, PNG, WEBP or HEIC) or PDFs attached to each request, taken straight from the phone.

Rule-checked requests

Only a contractor can request a payment; the new progress must be higher than the current one and no more than 100%, and there cannot be two pending requests for the same line item.

Rejection with a comment

The reason stays on the request and is cleared when the contractor resubmits it fixed.

Payment window

Requests are only processed within the week’s operating hours. The interface warns about it and the server enforces it.

Works with no signal

Projects, quotes and line items are stored on the device. Whatever is captured offline waits in a queue and is sent automatically on reconnect.

Roles

Administrator and contractor, each with their own screens and permissions.

Installable (PWA)

Installs on a phone or computer like any other app, without going through an app store.

How it is built

End-to-end engineering

Separate frontend and backend, joined by a versioned API (the door the app uses to request data from the server).

React 19 and TypeScript

TypeScript adds types to JavaScript to catch errors before running. Routing uses React Router and state uses Zustand.

FastAPI backend

FastAPI is a Python framework for building APIs. It runs asynchronously and validates every incoming field with Pydantic.

PostgreSQL and migrations

Data lives in PostgreSQL 16. Schema changes are applied with Alembic migrations: versioned scripts that update the database without losing data.

Exact amounts

Amounts are handled as exact decimals, not floating-point numbers, so balances never accumulate rounding errors.

Docker Compose

Docker packages each part in a container that runs the same on any server. There is one setup for development and another for production, with nginx serving the interface.

Continuous integration

On every change, GitHub Actions runs the migrations and backend tests and type-checks the frontend.

Offline and security

Designed for the job site

Offline-first with IndexedDB

With Dexie, a layer on top of IndexedDB (the browser’s built-in database), the app keeps local copies of projects, quotes, line items and requests.

Sync queue

Each operation made offline is stored with its destination and its data. When the connection returns it is sent in order, with a limited number of retries.

Service worker with Workbox

The service worker stores the app on the phone so it opens without internet; Workbox is the library that generates it.

Expiring JWT

After sign-in, the server issues a JWT (a signed token that proves who you are) that expires after 8 hours. Passwords are stored hashed with bcrypt.

Server-side rules

Role permissions and the payment window are validated in the backend; the interface only warns. If someone tries to bypass them, the server rejects the request.

Tested files and dates

Each piece of evidence is checked for type and size before it is stored. Automated tests simulate dates and times to verify the payment window.
