In plain words

What it is and why it matters

What is an ERP?

A system that puts in one place what usually lives in separate tools: the calendar, sales, suppliers, expenses and reports. The whole team works on the same information.

The problem

In an events business, appointments live in a calendar, quotes in loose documents, payments in chat messages and expenses in spreadsheets. Knowing which event is paid, what is missing and which supplier confirmed takes time and causes mistakes.

The solution

Núcleo follows each event from the first appointment to the last payment. The schedule also shows up in the team’s calendar, quotes come out as PDFs and the dashboard shows at a glance what has been collected and what is pending.

Step by step

From first contact to the event

Book the visit

Log the client’s visit and the appointment appears in Google Calendar on its own. If someone moves it there, it changes in Núcleo too.

Quote

Build the quote from a base package, extra items and payment terms, and download it as a PDF to send.

Plan the event

Once confirmed, the event gets its checklist of tasks and its assigned suppliers.

Collect and control

The dashboard shows collected income, pending payments and upcoming events, and expenses are logged by category.

Features

Your whole business, organized

Stop jumping between apps, sheets and messages: Núcleo brings it all together.

Two-way calendar sync

Creating, moving or deleting an appointment in Núcleo creates, moves or deletes it in Google Calendar. And when the change is made in the calendar, Google notifies Núcleo and it pulls the change back, with no duplicates.

PDF quotes

Client details, package, line items and payment terms in a document ready to send.

Packages

A catalog of service packages used as the starting point for each quote.

Events with a checklist

Each event has its record, its status and a to-do list the team ticks off until the big day.

Suppliers

A supplier directory to assign them to each event.

Expenses by category

Suppliers, decoration, maintenance, supplies, staff and more, with filters and the category with the highest spend.

Today’s dashboard

On sign-in you see collected income, pending payments, active events and the month’s summary, with upcoming events and payments to follow up.

Cash-flow reports

Income versus expenses, month by month.

Multi-user

Everyone signs in with their own account; only administrators can touch business data.

How it is built

Modern and maintenance-free

Serverless architecture: the cloud runs the code only when it is needed.

Serverless on Firebase

Serverless means no servers of your own: the backend runs as Cloud Functions on Firebase (Google’s cloud platform), functions that start when a request arrives and scale on their own.

React 18 and Vite

React frontend with validated forms (React Hook Form and Zod) and lightweight global state with Zustand. It is deployed on Firebase Hosting and set up as a PWA (an app you can install from the browser).

Real-time Firestore

Firestore is a NoSQL database (it stores documents instead of tables) that notifies every screen when something changes, so everyone sees the same data within a second.

Appointment triggers

When an appointment is created, changed or deleted, a trigger (code that runs on its own when the database changes) mirrors it in Google Calendar. It only reacts to changes in date, time, title or client, so it never loops.

Calendar webhook

Núcleo subscribes to changes in the main calendar: Google calls a webhook (an address that receives automatic notifications) and Núcleo downloads the events that changed.

Express API

Quotes and the Google connection go through an API (the door the frontend uses to request data from the server) built with Express and deployed as a Cloud Function.

Security

Everyone sees only what is theirs

Google OAuth 2.0

Sign-in and calendar access use OAuth 2.0, the standard Google uses to authorize an app without sharing your password with it.

Deny by default

Firestore rules deny anything not explicitly allowed. Business collections can only be read and written by administrators.

No self-promotion

A user can create and edit their profile, but cannot grant themselves the administrator role.

Rate limiting

The API limits how many requests it accepts in a time window to curb abuse.

Secrets out of the code

OAuth credentials are stored as Firebase secrets, never in the code.

Verified notifications

Every notification coming from Google is checked against an internal token before it is processed.
