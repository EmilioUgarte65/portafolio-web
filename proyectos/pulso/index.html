Encuestas de satisfacción

Encuestas que funcionan donde sea, haya o no señal.

Pulso es una PWA (app que se instala desde el navegador) para medir la satisfacción de los clientes en cada sucursal. Una tablet en modo kiosco hace preguntas con caritas, opciones o texto; las respuestas se guardan en el dispositivo y se sincronizan solas al volver la conexión. En la oficina, un panel muestra los resultados en tiempo real y los exporta a Excel y PowerPoint.

¿Qué es y para qué sirve?

¿Qué es?

Un sistema de encuestas con dos caras: la pantalla de kiosco, que el cliente contesta al salir, y el panel de administración, donde se configuran las preguntas y se leen los resultados.

El problema

Las encuestas en papel nadie las captura y las de enlace casi nadie las contesta. Si la encuesta depende de internet, cada caída de la red es una opinión perdida, y los resultados llegan tarde.

La solución

Una pregunta a la vista que se responde con un toque y no se pierde aunque no haya red. Si la calificación es mala, pregunta qué mejorar; si la satisfacción baja de la meta, avisa a la oficina.

Paso a paso

Así funciona una encuesta

El cliente califica

Toca una carita, elige una opción o escribe un comentario. Las preguntas abiertas se pueden omitir.

Seguimiento

Si califica mal, aparece una pregunta de seguimiento como «¿Qué podemos mejorar?».

Se guarda y se envía

Al terminar, la encuesta completa se guarda en el dispositivo y se envía en un solo lote. Si el cliente se va a medias, se reinicia y se descarta.

La oficina lo ve

El panel se actualiza en vivo. Si el índice baja de la meta llega una alerta, y los reportes salen a Excel o PowerPoint.

Capacidades

Mide la satisfacción sin pretextos

Pensada para sucursales con mala señal y para que cualquiera la use sin capacitación.

Captura sin internet

Cada respuesta se guarda al momento en la tablet. El personal nunca se queda esperando señal para seguir encuestando.

Tres tipos de pregunta

Caritas con etiquetas editables, opción múltiple y texto abierto.

Preguntas de seguimiento

Aparecen o no según la calificación que dio el cliente.

Modo kiosco

Se reinicia sola tras un rato sin uso, con más tiempo en las preguntas de texto. El contador no corre en la primera pregunta, para no reiniciar cuando nadie ha empezado.

Horarios y límites

Franjas horarias con un límite de encuestas; al llenarse muestra un agradecimiento distinto al mensaje de «fuera de horario».

Encuestas por sucursal

Preguntas agrupadas en encuestas y ordenadas arrastrando y soltando.

Panel en tiempo real

Métricas, tendencias e índice de satisfacción por sucursal y por pregunta, con los comentarios abiertos filtrables.

Excel y PowerPoint

Datos con filtros en .xlsx y una presentación con gráficas en .pptx.

Alertas

Notificaciones push (avisos que llegan aunque la app esté cerrada) cuando la satisfacción cae por debajo de la meta.

Cómo está construido

Una PWA con servidor propio

Un solo proyecto con la app de kiosco, el panel y la API.

React 18, TypeScript y Tailwind

Interfaz en React con TypeScript (JavaScript con tipos) y estilos con Tailwind CSS, compilada con Vite.

API con Express 5

Una API REST (la puerta por la que la app le pide datos al servidor, organizada por recursos) con rutas para votos, preguntas, sucursales, encuestas, métricas, usuarios y auditoría, escrita en TypeScript.

Prisma y SQL Server

Prisma es un ORM: una capa que traduce el código a consultas de base de datos. Los datos viven en SQL Server.

Tiempo real con Socket.io

Socket.io mantiene una conexión abierta con el panel para que los votos nuevos aparezcan sin recargar la página.

iPads antiguos

Un plugin de compatibilidad genera una versión para Safari 12, así siguen sirviendo las tablets que ya no se actualizan.

QA aislado

Un ambiente QA (de pruebas) con su propia base de datos en Docker, separado por completo de producción.

Sin internet y seguridad

Confiable en el peor internet

Offline-first con IndexedDB

Offline-first quiere decir que la app trabaja primero en el dispositivo. Con Dexie, una capa sobre IndexedDB (la base de datos interna del navegador), cada voto se guarda como «pendiente» antes de intentar enviarse.

Reintentos y limpieza

Si no hay red, se reintenta en el siguiente ciclo; tras varios fallos, el voto queda marcado para revisión. Los ya sincronizados se borran del dispositivo después de una semana.

Envío por lote

La encuesta completa viaja en una sola petición, así no quedan respuestas sueltas de una encuesta a medias.

JWT con renovación

El acceso usa JWT (un token firmado que demuestra quién eres): uno de acceso de corta duración y otro para renovarlo. Las contraseñas se guardan cifradas con bcrypt.

Dos roles

Administrador, con el panel completo, y sucursal, con la pantalla de kiosco y su propio tablero.

Bitácora de auditoría

Cada acción en el sistema queda registrada: quién hizo qué y cuándo.
