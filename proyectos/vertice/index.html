Gestión de obra a la medida

Presupuestos, avances y pagos de cada obra, en una app que sigue sin señal.

Vértice es una aplicación full-stack (con interfaz y servidor propios) hecha a la medida para administrar proyectos de obra con proveedores externos. Cada proyecto tiene su presupuesto y sus cotizaciones por partida; el proveedor reporta su avance con fotos y pide su pago, y el administrador lo aprueba o lo rechaza. Es offline-first: trabaja primero en el dispositivo y sincroniza cuando vuelve la señal.

¿Qué es y para qué sirve?

¿Qué es?

Una app de gestión hecha para un proceso concreto: controlar cuánto se ha avanzado y cuánto se ha pagado en cada partida (cada concepto de trabajo) de una obra.

El problema

Los avances llegan por mensaje, las fotos se pierden en el chat y los pagos se apuntan en hojas de cálculo. Así es fácil pagar dos veces el mismo avance o pagar de más, y en la obra muchas veces no hay señal.

La solución

Cada pago nace de un avance comprobado con evidencia y queda ligado a su partida. El sistema calcula lo pagado, lo disponible y el avance del proyecto, y no deja pasar solicitudes que rompan las reglas.

Paso a paso

Así fluye un pago

Arma el proyecto

El administrador da de alta el proyecto con su presupuesto y le asigna proveedores.

Cotiza por partida

El proveedor registra su cotización dividida en partidas, con subtotal, IVA (el impuesto al valor agregado) y total.

Reporta el avance

Desde la obra, el proveedor indica el nuevo porcentaje de una partida y adjunta fotos o PDF, aunque no haya señal.

Aprueba o rechaza

Si el administrador aprueba, el avance y el saldo se actualizan solos; si rechaza, deja un comentario para que el proveedor corrija y reenvíe.

Capacidades

Tu proceso, en una app

Reemplaza hojas de cálculo, chats y formatos en papel por una herramienta hecha para el proceso real.

Proyectos con presupuesto y avance

Por proyecto: cuánto se ha gastado, cuánto queda, qué porcentaje del presupuesto se ha usado y el avance operativo promedio de sus cotizaciones.

Cotizaciones por partida

Cada partida tiene su monto autorizado; lo pagado y lo disponible se recalculan con cada aprobación.

Evidencias

Fotos (JPG, PNG, WEBP o HEIC) o PDF adjuntos a cada solicitud, tomados directo del celular.

Solicitudes con reglas

Solo un proveedor puede pedir un pago; el nuevo avance debe ser mayor al actual y no pasar del 100 %, y no puede haber dos solicitudes pendientes para la misma partida.

Rechazo con comentario

El motivo queda en la solicitud y se borra cuando el proveedor la reenvía corregida.

Ventana de pagos

Las solicitudes solo se procesan dentro del horario operativo de la semana. La interfaz lo avisa y el servidor lo hace cumplir.

Funciona sin señal

Proyectos, cotizaciones y partidas se guardan en el dispositivo. Lo que se captura sin conexión espera en una cola y se envía solo al reconectar.

Roles

Administrador y proveedor, cada uno con sus pantallas y sus permisos.

Instalable (PWA)

Se instala en el teléfono o la computadora como una app más, sin pasar por una tienda de apps.

Cómo está construido

Ingeniería de extremo a extremo

Frontend y backend separados, unidos por una API (la puerta por la que la app le pide datos al servidor) con versiones.

React 19 y TypeScript

TypeScript agrega tipos a JavaScript para detectar errores antes de ejecutar. Las rutas van con React Router y el estado con Zustand.

Backend con FastAPI

FastAPI es un framework de Python para construir APIs. Trabaja de forma asíncrona y valida cada dato que entra con Pydantic.

PostgreSQL y migraciones

La información vive en PostgreSQL 16. Los cambios de estructura se aplican con migraciones de Alembic: scripts versionados que actualizan la base sin perder datos.

Montos exactos

Los importes se manejan como decimales exactos y no como números de punto flotante, para que los saldos no acumulen errores de redondeo.

Docker Compose

Docker empaqueta cada parte en un contenedor que corre igual en cualquier servidor. Hay una configuración para desarrollo y otra para producción, con nginx sirviendo la interfaz.

Integración continua

En cada cambio, GitHub Actions corre las migraciones y las pruebas del backend, y revisa los tipos del frontend.

Sin internet y seguridad

Pensado para la obra

Offline-first con IndexedDB

Con Dexie, una capa sobre IndexedDB (la base de datos interna del navegador), la app guarda copias locales de proyectos, cotizaciones, partidas y solicitudes.

Cola de sincronización

Cada operación hecha sin señal se guarda con su destino y sus datos. Al volver la conexión se envía en orden, con un número limitado de reintentos.

Service worker con Workbox

El service worker guarda la app en el teléfono para que abra sin internet; Workbox es la librería que lo genera.

JWT con caducidad

Al iniciar sesión, el servidor entrega un JWT (un token firmado que demuestra quién eres) que vence a las 8 horas. Las contraseñas se guardan cifradas con bcrypt.

Reglas en el servidor

Los permisos por rol y la ventana de pagos se validan en el backend; la interfaz solo avisa. Si alguien intenta saltárselas, el servidor rechaza la petición.

Archivos y fechas probados

Cada evidencia se revisa por tipo y tamaño antes de guardarse. Las pruebas automáticas simulan fechas y horas para comprobar la ventana de pagos.
